## 用户反馈与范围

2026-10-19：产品反馈“框和文字没对齐”，并指出标题 1、2 的字号落差太大。截图中的任务框明显高于文字。本反馈不是格式切换功能的验收通过；保留 [格式切换记录](fix-format-toggle-v0.2.0.pending-acceptance.md) 的待验收状态。

本轮检查实际任务清单首行对齐、常用字号下的换行与嵌套，以及 H1–H6 的字号递进。提供合成文稿在真实候选界面中的前后对比和参数，不改写用户文稿。

同日产品补充：“另外由于二级太小，后面的字体大小应该也要同步调整下”。按整套 H1–H6 调整，而非只缩小一级标题；修复原有 H5 大于 H3/H4 的层级倒挂。

## 验收标准

1. 未完成、已完成任务的方框对齐文字第一行；多行和嵌套任务不按整段高度居中。
2. 普通无序、有序列表的标记仍与首行对齐；任务勾选和格式切换可正常使用。
3. H1 与 H2 保留层级但缩小落差；H1–H6 不出现低级标题比高级标题更大的倒挂。
4. 浅色、纸张、深色主题及正文 13/16/24px 下均检查，提供实际截图和测量数据。
5. 完成 `npm.cmd test`、`npm.cmd run build` 及相关 Electron 检查，交付独立候选供产品确认。

## 原因与实现

- 与工作区原始基线 `01c54cc` 的样式对照，H1/H2 原本就是 `2.05em / 1.42em`，不是上一轮格式命令引入的字号变化。H5/H6 没有应用层覆盖，继承 Crepe 默认 `1.5em / 1.125em`，造成低级标题倒挂。
- 清单组件使用固定 `32px` 标记容器，但正文首段有 `.3em` 上边距、`4px` 内边距和 `1.85` 行高。实测默认 16px 时任务框中心高于首行中心约 `7.6px`，24px 时约 `17.4px`。
- 将标题级别及清单排版放入 `src/editor-typography.css`。H1–H6 使用 `2 / 1.7 / 1.45 / 1.25 / 1.125 / 1.0625em`；默认 16px 时为 `32 / 27.2 / 23.2 / 20 / 18 / 17px`。H1/H2 落差从约 44% 缩小到约 18%。
- 清单标记的容器高度、上边距与首行共享参数，多行任务仍靠第一行对齐。保留 24px 的图标与点击区域宽度。
- 颜色参数及正文字号保持现有设置；产品已在候选界面确认本项效果。

## 产品验收操作

1. 使用桌面“墨页 格式修复候选版”或 `release/0.2.0-rc.3/Start-acceptance.cmd` 打开新候选，查看自建的 `typography-acceptance.md`。
2. 比较 H1 与 H2，以及 H3–H6，确认二级及后续标题足够醒目且层级自然。
3. 观察未完成、已完成、多行及嵌套清单，方框应与第一行文字对齐；普通列表标记也应对齐。
4. 在写作设置中调整字号、主题或衬线字体，检查是否舒适；点击勾选再 Ctrl+Z，状态应恢复。
5. 把光标放在标题里，按相同级别的 Ctrl+1–6 取消，确认上一轮格式切换行为仍正常。

候选使用独立 `acceptance-profile`，原 rc.2 及其文稿保留。桌面候选入口更新为 rc.3；已打开的旧窗口继续运行，不会自动换成新版本。
