## 反馈与范围

用户反馈：三个反引号生成的代码块文字太淡，截图为暖纸主题，普通文字与代码块内文字对比明显。用户提到以前有类似淡化问题已修复，需要核对相关实现。

用户要求：颜色或对比度不确定时，展示实际效果和颜色参数，由产品评价。开发自测后仍须用户明确验收，才能正式归档。

本次检查即时编辑中的无语言代码块、有语法高亮的代码块、三种主题及专注模式；验证切换主题不丢光标、编辑内容和撤销历史。

## 验收覆盖项

- [x] 暖纸与素白主题下，无语言代码块中的中文/英文清晰可读。
- [x] 深夜主题保持清晰，不出现浅底浅字或深底深字。
- [x] 代码语法高亮仍有区分，行号、光标、选区、当前行协调。
- [x] 专注模式非当前块保留可读性，当前代码块与此前整组高亮行为一致。

- [x] 提供实际软件截图、前后颜色与对比度；产品明确确认效果。

## 调查与实现

根因：Crepe 的 CodeMirror 功能默认使用 One Dark。项目只覆盖了代码块背景色，未替换其文本和语法主题；暖纸/素白出现“浅灰字 + 浅色底”。专注模式对非当前块使用 0.8 不透明度，进一步降低了可读性。

历史核对：基线导入提交中已存在选择工具栏对比度修复、专注模式按整组高亮并保留 0.8 不透明度的处理。当前 Git 历史未拆出这些处理的独立提交，不能确认用户回忆的具体是哪一次；本次定位到的是独立的代码块主题问题。

实现：

- 新增 `src/codeBlockTheme.ts`，保留 One Dark 的语法 token 分类，将颜色映射到墨页主题变量。无语言文字跟随正文色；光标、行号、当前行、选区和工具提示也使用相应主题色。
- 新增 `src/code-block.css`，为浅色和深色提供不同语法色，覆盖尚未挂载编辑器时的代码占位文字；保留既有代码背景、字号与专注模式透明度。
- 主题变量在 CSS 中切换，无需重建代码块编辑器；懒加载的代码块也读取当前主题。
- 帮助页版本改为构建时读取 package.json；package.json 与锁文件根版本同步为 0.1.5-rc.1。
- 建立 docs/design、docs/implementation、文档命名规范及 AGENTS.md 约定。评论设计已迁移，功能实现仍按约定等待本修复产品验收后推进。

- 程序：`release/0.1.5-rc.1/Moye-win32-x64/Moye.exe`。
- 启动入口：`release/0.1.5-rc.1/Start-acceptance.cmd`；入口设置独立 acceptance-profile 并打开 acceptance.md，正式版设置和用户文稿保持独立。
- 构建指纹：app.asar SHA-256 `d1e14db5b935b801c6ad5a7b277ad21368d3239f48299a5a480068e770d8af08`。

1. 打开候选版，先看暖纸主题的普通代码块与 Python/JavaScript 示例，评价是否偏淡、太重或颜色不舒服。
2. 通过“主题”切换素白、深夜，检查文字、行号、光标、选择文字后的效果。
3. 按 F8 开启专注模式，分别点正文与代码块，检查非当前代码块仍能阅读。
4. 在代码块里输入，切换主题继续输入，再撤销；也可以在文稿末尾输入三个反引号并回车，新建代码块。
5. 明确反馈通过、部分通过或需调整的主题/颜色；确认后才去掉 pending-acceptance 后缀，并写入正式 CHANGELOG。
